  `main`, found in flight rather than groomed.
- **What:** guarded the two Krumhansl–Schmuckler profile tuples in

## The actual defect

`main` went red at pipeline #45 (`41593e4`, the PV3 merge):

```
+ uv run ruff check .           → All checks passed!
+ uv run ruff format --check .  → Would reformat: app/jobs/extractors/midi_features.py
                                  1 file would be reformatted, 66 already formatted
```

**The file was the symptom; the gate list was the defect.**
`.woodpecker/backend.yml`'s `lint` step runs two commands and `loop.md`
listed one. A ticket could therefore pass every gate the loop knows about
and still redden `main` — and one did. Frontend gates were checked at the
same time and match `.woodpecker/frontend.yml` step-for-step; `ruff format`
was the only drift.

## Why `fmt: off` rather than accepting the reformat

`ruff format` wanted both profiles exploded to one float per line — 24 lines
for what is conceptually a single 12-element vector indexed by semitone. The
whole point of the literal's shape is that you can read it as a row and
compare it against Krumhansl (1990) Table 3.1. A comment says so, so the
next person doesn't "tidy" the guard away. The values are untouched.

## The second mistake, recorded because it is the more expensive one

PV3's PR #20 was merged **without reading its pipeline**. Branch pipelines
#43 and #44 had already failed. Nothing subtle happened here — the red was
on screen and went unread, because the preceding ticket (PV2) had set the
habit of checking that CI was *running* and merging anyway.

`loop.md`'s Merge policy now states it outright: green means CI too; poll
the branch SHA's pipelines and merge only when every one has succeeded;
`pending`/`running` is not a licence to merge.
