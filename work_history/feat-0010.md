## Where the judgment actually went

Krumhansl–Schmuckler correlation over the duration-weighted pitch-class
histogram, 12 rotations × major/minor. The decision that matters is that
**the best correlation *is* the confidence** — a weak guess gets the same
number a strong one does, so the panel can read low confidence as "don't
trust this" instead of the function silently declining to answer.

Verified independently rather than taken from the subagent's report:

| fixture | key_guess | confidence |
|---|---|---|
| C major scale | `C major` | 0.7564 |
| A minor arpeggio | `A minor` | 0.9240 |
| chromatic run | `C major` | **0.0000** |

A chromatic run's histogram is perfectly flat — zero variance, correlates
with nothing — so it scores 0.0 with a deterministic tie-break the code
calls "all a 0.0-confidence tie deserves". A note-less file gets **no**
`key_guess` and no histogram at all, rather than a fabricated key.
(The arpeggio outscoring the scale is expected: three strong pitch classes
match the minor profile more tightly than seven equally-weighted ones match
the major profile.)

## Auto-enqueue cannot break upload

The enqueue runs in its own SAVEPOINT (`db.begin_nested()`), so a failure —
e.g. a real race against a concurrent identical upload hitting the
run-identity unique index — rolls back only itself; the `IdeaAsset` already
flushed in the same transaction still commits. Dedup is not hand-rolled: the
run is keyed on the asset's sha256 through `get_or_create_queued_run`'s
existing identity index.

## Known gap, left deliberately

`python -m app.jobs.worker` does not import `app.jobs.extractors`, so
`midi-features` would be unregistered if run as a standalone process.
Nothing deploys that path — the embedded worker gets it via `main.py`.
Documented in code rather than fixed, since fixing it means bending
`worker.py`'s registration invariant for a path nobody uses.

## Friction — this ticket went red on main

Two separate mistakes, both mine, both fixed at the source in fix-0006:

1. **`loop.md`'s gate list did not match CI.** `.woodpecker/backend.yml`'s
   `lint` step runs `ruff check .` **and** `ruff format --check .`;
   `loop.md` listed only the first. PV3 passed every gate the loop knew
   about and was still red on the server.
2. **PR #20 was merged without reading its pipeline.** Branch pipelines #43
   and #44 had *already failed*. The red was visible and went unread. The
   preceding ticket (PV2) set the bad habit: CI was merely *running* there
   and the merge went ahead anyway.

A third, smaller one: a gate run piped through `tail` printed `FORMAT OK`
after `ruff format --check` had actually failed — `tail`'s exit code masks
the command's. Same class as the PV2 wrapper whose summary contradicted its
own body.

And the deployed check's first run reported two false FAILs: it searched for
"key guess" inside `.meta-rail, aside`, but the properties panel renders
elsewhere. Its own `.prop-lineage` assertion had *already* found six
`midi-features 1.0.0` badges in the same run — the evidence that the
pipeline worked was sitting in the passing line directly above the failing
one. Querying the API settled it in one call.
