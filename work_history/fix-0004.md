## What the one line actually bought

Five spec files had sat in `app/e2e/` unable to run on this laptop for the
whole life of the repo, because `devices['Desktop Chrome']` with no
`channel` sends Playwright looking for a *bundled* chromium that disk
policy forbids installing. `@playwright/test`/`playwright-core` 1.56.1 were
in `app/node_modules` the entire time, and Chrome 152 was in
`/Applications`. Nothing was missing except the pin.

First-ever run of the suite on this machine:

```
34 passed (16.5m)
[exited with code 0]
```

All five specs: `drills` (28 tests), `library`, `piece`, `session`,
`stats-and-sketchbook`. Serial, against the auto-started dev server on
:5173.

**Zero-download claim, verified rather than asserted:**
`~/.cache/ms-playwright` did not exist before the run and does not exist
after it. The only artifacts written were the gitignored
`playwright-report/` (536K) and `test-results/` (4K).

## Why it was worth a ticket rather than a drive-by

`e2e/stats-and-sketchbook.spec.ts` pins the Sketchbook mock markup —
`.sketch-grid`, `.lyric-block .marker`, `.chord-row .chord` (exactly 5),
`.harmony-score svg g.note`. feat-0007 (SB3a) moved that markup between
files and had to prove it verbatim by hand with `diff <(git show HEAD:…)`,
because no gate on this laptop could catch a break in it. That gap is now
closed: SB3b, SB7 and RC2 all inherit a live browser gate instead of the
same manual argument.

## Friction log

- The e2e run takes **16.5 minutes** (`fullyParallel: false`, 60s timeouts,
  Verovio engraving in most specs). Too slow for the per-ticket gate list
  in `loop.md`, which is why it stays a *substrate* to be invoked by
  acceptance criteria rather than a fifth default gate. A future ticket
  could enable parallel workers; not attempted here (out of scope).
- Piping the run through `tail` buffered all output, so a long-running
  suite looked indistinguishable from a hang for ten minutes. The live
  progress signals that resolved it were the dev server answering 200 and
  `test-results/.playwright-artifacts-N` directories appearing — those are
  per-worker temp dirs, **not** failure traces, which is the opposite of
  what they look like mid-run.
- The claim commit for this ticket went to `main` before the branch work,
  per the skill's rule; `git reset --hard` to sync the branch onto it was
  refused by the permission classifier, and `git merge --ff-only main` is
  the equivalent that is allowed.
