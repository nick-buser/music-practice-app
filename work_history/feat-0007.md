## Sidebar count

`NAV` in `Sidebar.tsx` is a module const and cannot read live state, so
`Sidebar` gained an optional `counts` override falling back to each item's
static value, leaving the `.count`/`.active` markup untouched. `App.tsx`
computes the live number via its own `useIdeas(true)`, independent of the
instance `SketchbookLive` owns. Accepted trade-off: two `GET /v1/ideas`
while the tab is open, and a badge that trails a capture until its next
fetch. Lifting the hook into shared context is the fix if that ever reads as
a bug; it is a bigger change than SB3a should carry.

## Contract bug found in flight, filed not fixed

The SB2 streaming download route is documented in `openapi.json` as
`{"content": {"application/json": {"schema": {}}}}` although it returns real
binary — the SB2 deploy check round-tripped 1 MB with a correct
`Content-Type` and `ETag`. Every generated client therefore types the
response as JSON `unknown`, which is why no typed `downloadIdeaAsset` exists.
Filed as **FX1** in the grooming doc (T0). Note what this says about gates:
SB2 was green everywhere and its runtime check passed, because the defect is
in the *documentation of a route that works*.
