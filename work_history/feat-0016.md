## What the format is actually promising

The manifest is a **file format, not a wire format**, and that single
distinction drove most of the design. Everything in `app/schemas/` inherits
`CamelModel` because a JS client reads it. `IdeaManifest` does not: its
fields are snake_case, matching the database columns `docs/sketchbook.md`
already documents, because the reader is a human — or an importer that is
not this codebase — possibly a decade from now. Getting that backwards
would have made the ten-year artifact an implementation detail of today's
frontend conventions.

**Links travel by `handle`, never by id.** This is the format's whole
point. A bundle has to survive import into a database where every uuid is
different; `handle` is the one identifier the doc guarantees is stable
prose identity ("#183" always means handle, never `id`). `id` is still
carried, but explicitly as provenance only — "this idea's id in the
database that exported it" — and `import_bundle` never trusts it.

**`mentions` edges are deliberately not exported.** They are recomputed by
delete-then-insert from the body on every save (`_sync_mentions`). Carrying
them would round-trip a value the importer immediately discards — and worse,
could resurrect an edge a body hand-edited between export and import no
longer justifies. `import_bundle` goes through the real repository
functions so they get recomputed instead. There is a test pinning this,
because it is exactly the sort of thing a later reader "fixes".

**`import_bundle` recreates, it does not restore.** Fresh uuid always; same
`handle` when free, reminted through the production `_next_handle` path
when not; bytes re-put through the store, where content-addressing collapses
identical bytes rather than duplicating them. A link whose target handle is
absent in the destination is dropped silently, matching how `_sync_mentions`
already treats unknown handles — consistent, and the alternative (raising)
would make a partial bundle unimportable for no gain.

## The scope tension, named rather than smoothed over

`properties` is always `[]`. The groomed scope said "properties empty until
PV1 lands, shape fixed now" — but **PV1, PV2 and PV3 have all since
landed**, so an idea can genuinely carry extracted properties today and this
bundle will not include them. A PR titled "the ten-year guarantee" that
ships a lossy export is a real tension, and it was flagged in the PR body
rather than quietly resolved either way.

Landed as scoped, for two reasons: the acceptance criteria do not mention
properties, and the manifest shape is already fixed so populating it later
needs no `schema_version` bump. Filed in the grooming doc's Deferred list
as a small follow-up, which also has to decide whether `import_bundle`
recreates `ExtractionRun` rows (today an imported asset's `run_id` is always
`None`, tested explicitly so the behaviour is pinned rather than accidental).

The general point for the loop: when a grooming doc's assumption has expired
between grooming and implementation, the fix is to say so out loud and file
it — not to silently widen the ticket, and not to silently ship the gap.

## Two additions beyond the groomed field list

- **`mime` on `ManifestAsset`.** `IdeaAsset.mime` is required and
  non-derivable: unlike `bytes` (recomputed on re-put) and `storage_key` (a
  pure function of `sha256`), it cannot be reconstructed from the file's
  bytes without a sniffing step this app has never had. Without it
  `import_bundle` cannot construct a valid row at all. Not scope creep —
  the round-trip criterion is unsatisfiable without it.
- **`user_id` on `import_bundle`.** Every repository function here is
  explicitly user-scoped, and an importer has no HTTP request to pull a
  `CurrentUser` from.

## Path safety

Every bundle path is validated against traversal (`..`, absolute, leading
`/`) on all three paths: directory write, zip build, and import. `filename`
comes from user upload, and the composed `assets/<revision>/<filename>` is
therefore attacker-influenced. This is a personal app, but a bundle is
precisely the kind of object people eventually receive from someone else,
so refusing beats sanitising.

## Friction log

- **Pyright strict has no stubs for `yaml`**, so `safe_load`'s return
  cascades into `reportUnknownVariableType` even after an explicit `Any`
  annotation — `isinstance(raw, dict)` narrows to `dict[Unknown, Unknown]`,
  not `Any`. Resolved with `cast(dict[str, Any], raw)`, the same workaround
  `app/storage.py` already documents for boto3. Worth knowing before the
  next stub-less-library ticket.
- **`@contextmanager` with `-> Iterator[T]` now trips `reportDeprecated`**
  under this pyright version, which wants `Generator[T, None, None]`. Not
  documented in any repo convention; only discovered by running the gate.
