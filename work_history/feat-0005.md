## Link kinds came from the doc, not from invention

The eight kinds — `derived_from`, `variant_of`, `resembles`,
`might_fit_with`, `inspired_by`, `incorporated_into`, `responds_to`,
`mentions` — are verbatim from `docs/sketchbook.md`'s `idea_links` table,
and were cross-checked identical across the `IdeaLinkKind` Literal, the
model `CheckConstraint`, and the migration `CheckConstraint`. Verified
independently in the orchestrating session by grepping the doc, not taken
from the implementer's report.

## Handle minting

`max(handle) + 1` per user, computed inside the insert transaction and
deliberately **without** a `deleted_at IS NULL` filter — that is precisely
what stops a soft-deleted idea's handle being reused, which is an explicit
criterion. Concurrent creates can still race to the same max, so the insert
retries on the unique violation, bounded at five attempts.

The test for this is worth copying. The obvious version — create two ideas,
assert handles 1 and 2 — passes even against a completely broken retry,
because sequential creates never race. The implemented test instead
monkeypatches `_next_handle` to return a stale value once and asserts the
retry *recovers*. It tests the mechanism rather than the happy path.

Caveat recorded at the call site: the `db.rollback()` in that retry assumes
`create_idea` is the first write of its request. A future caller that writes
before creating an idea would silently lose that write.

## Both known traps guarded

- **FK ordering** (OPS2, hit again in PV1): `create_idea` flushes the idea
  before `_sync_mentions` adds any `IdeaLink`, commented and pointing at the
  longer explanation in `repositories/provenance.py`. An
  `@pytest.mark.integration` test covers it against real Postgres, since the
  SQLite suite structurally cannot.
- **`to_camel` aliases** (PV1): every new wire field checked; none of SB1's
  names trip the digit→letter capitalisation bug.

## Follow-ups found, not fixed

- `get_idea_links` does not filter the *other* idea by `deleted_at IS NULL`,
  so a link to a since-soft-deleted idea still surfaces in `linksIn`/
  `linksOut` with that idea's stale handle and title; soft-deleting an idea
  likewise leaves its `IdeaLink` rows behind.
- `list_ideas` applies the `kind`/`tag` filters in Python after a single SQL
  fetch, because JSONB containment has no portable SQLite equivalent. Fine
  at single-tenant scale; SB5 owns real search.
- PATCH follows the existing house convention (`if data.x is not None`), so
  a client cannot explicitly null `title`/`key`/`meter`/`bpm` once set.
  Pre-existing in `chords.py`/`sessions.py`, not introduced here.
