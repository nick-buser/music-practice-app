## The design decision worth keeping

A 200 MB upload cap is trivially implementable by reading the body and
checking its length — and that version passes every acceptance criterion
while silently destroying the reason MD1 spooled uploads in the first place.

`_CappedStream` instead counts bytes on each `read()` and raises 413
mid-read. Because both stores only *finalise* an object after their read
loop completes (`put_object` for S3, the dict insert for memory), a rejected
upload cannot leave a partial object behind — and that is **asserted**
(`stat(...) is None`, `put_count == 0` after a 413) rather than argued in a
comment. The `Content-Length` pre-check is labelled in-code as best-effort
only: Starlette has already parsed the multipart body by the time route code
runs, so genuine early rejection belongs at the ingress.

## The FK trap was checked and deliberately not guarded

An asset always attaches to an `Idea` loaded from a prior transaction, so
there is no same-transaction parent+child insert of the kind that bit PV1
and SB1 — no flush is needed, and adding one would be cargo-culting.
`create_asset`'s docstring records that explicitly, contrasted against
`create_idea`'s load-bearing flush. Three tickets running have now touched
this pattern; documenting the *absence* is what stops the next one adding a
pointless flush.

`to_camel` was checked for every new field name (`sha256`, `storage_key`,
`run_id`, `new_revision`, `idea_id`, `asset_id`, …). None trip the
digit-boundary bug, so no explicit alias was needed on the schemas.

## Deferred FK resolved

The grooming doc assigned `idea_assets.run_id → extraction_runs.id` to
whichever of SB2 / PV1 landed **second**. PV1 landed first, so
`0004_idea_assets` adds it. That open question is now closed.

## Open judgment call, left for PV5

The upload route does **not** expose `run_id` — the groomed route spec lists
only `file`, `role`, `new_revision`. The column, FK, migration and an
optional `repo.create_asset(run_id=...)` parameter are all in place, but the
route always passes `None`. `docs/sketchbook.md` line 172 describes a
`role: render` asset *with* `run_id` set as the target shape, which PV5
(`midi-render` previews) needs. Whoever picks up PV5 should wire it.
