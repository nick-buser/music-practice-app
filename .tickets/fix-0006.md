## Description

**Not groomed** — a hotfix for red `main`, found in flight.

`main` went red at pipeline #45 (`41593e4`, the PV3 merge). The backend
`lint` step failed:

```
+ uv run ruff check .           → All checks passed!
+ uv run ruff format --check .  → Would reformat: app/jobs/extractors/midi_features.py
                                  1 file would be reformatted, 66 already formatted
```

**Root cause is the gate list, not the file.** `.woodpecker/backend.yml`'s
`lint` step runs *two* commands — `ruff check .` **and**
`ruff format --check .` — but `.tickets/loop.md`'s Gates section only listed
the first. So PV3 passed every gate the loop knows about and still went red
in CI, and the loop merged it. Any future backend ticket could do the same.

Second, compounding error: PV3's PR (#20) was merged without checking its
pipeline. Branch pipelines #43 and #44 had **already failed** before the
merge — the red was visible and went unread.

## Notes

The formatter wanted to explode the two Krumhansl–Schmuckler profiles to one
float per line — 24 lines for what is conceptually a single 12-element
vector indexed by semitone. Guarded with `# fmt: off` / `# fmt: on` and a
comment saying why, rather than accepting a layout that destroys the
row-to-row comparison against Krumhansl's published table. The one genuine
formatting fix (a `raise` that fits on one line) was applied normally.
