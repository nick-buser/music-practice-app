## Description

Groomed as **FX3** in `.tickets/_grooming-sketchbook-and-media.md`.

**Tier:** T0 (a CSS rule)
**Depends on:** — (SB3b shipped the surface)
**Found:** 2026-09-02, in SB3b's deployed screenshot on `soundings-dev`.

**What:** `IdeaPage`'s headline renders the fallback `(untitled capture)` in
the large italic serif, and on idea #1 it runs past the right edge of its
card and is clipped mid-word with no ellipsis. Purely cosmetic — nothing
functional depends on it — but it is the first thing you see on any idea
that has no title yet, which is most of them by design
(docs/sketchbook.md: "Title... come later, or never").

**Fix:** a wrap/`overflow-wrap`/`text-overflow` rule on the headline in the
"IDEA PAGE" section of `app/src/styles/app.css`.

## Notes

**The grooming doc's suggested resolution is not reachable here.** It says
"Decide whether long titles should wrap to a second line or ellipsize;
wrapping is likelier right for a sketchbook." But the headline is an
`<input class="idea-title-input">` (`app/src/views/IdeaPage.tsx`), and an
`<input>` is a single-line control — it cannot wrap without changing the
element to a `<textarea>` or contenteditable, which is a behaviour change
well beyond a T0 CSS rule. Ellipsis is the reachable option.

**Likely root cause, to confirm rather than assume:** the input sits inside
`<div style={{ flex: 1 }}>` in a flex row. A flex item's default
`min-width: auto` refuses to shrink below its content's intrinsic width,
and an `<input>`'s intrinsic width comes from its default `size` — so the
flex item can be forced wider than the card, which is exactly the "runs past
the right edge of its card" symptom. If so the fix is `min-width: 0` on the
flex child plus `text-overflow: ellipsis` on the input, not a wrap rule.
