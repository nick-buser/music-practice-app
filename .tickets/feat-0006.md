## Notes

**This migration owns the `run_id` FK.** The grooming doc assigns
`idea_assets.run_id → extraction_runs.id` to whichever of SB2 / PV1 lands
second. PV1 landed first (feat-0004), so `0004_idea_assets` adds it.

**Roles are verbatim from the doc.** All eleven
(`melody|harmony|bass|drums|full|render|score|rpp|reference|image|other`)
come from `docs/sketchbook.md` line 77 and were cross-checked identical
across the Literal, the model `CheckConstraint` and the migration.

**The size cap is enforced mid-stream, deliberately.** MD1's design point is
that a large upload never sits whole in memory; a cap that buffered the body
first would undo that while still passing every test. `_CappedStream` counts
bytes per read and raises 413 mid-read. Because both stores only finalise an
object after their read loop completes, a rejected upload cannot leave a
partial object — asserted directly against `MemoryMediaStore`
(`stat(...) is None`, `put_count == 0`), not merely argued. The
`Content-Length` pre-check is documented in-code as best-effort: Starlette
has already parsed the multipart body by the time route code runs, so real
early rejection belongs at the ingress.

**No flush guard needed here, and that is recorded as a decision.** An asset
always attaches to an idea loaded from a prior transaction, so there is no
same-transaction parent+child insert of the kind that bit PV1 and SB1.
`create_asset`'s docstring says so explicitly, contrasting it with
`create_idea`'s load-bearing flush — so a later reader sees a considered
absence rather than an oversight.

**Open judgment call for review:** the upload route does not expose `run_id`
as an input — the groomed route spec lists only `file`, `role`,
`new_revision`. The column, FK and migration are fully implemented and
`repo.create_asset` takes an optional `run_id` for a future caller, but the
route always passes `None`. `docs/sketchbook.md` line 172 describes a
`role: render` asset *with* `run_id` set as a target shape, which PV5
(`midi-render` previews) will need. Whoever picks up PV5 should wire it.

**Follow-ups found, not fixed:** `0001_initial.py` still uses raw
`postgresql.JSONB()`, so a from-scratch `alembic upgrade head` cannot run
against SQLite (pre-existing; `0002`–`0004` all avoid it). The frontend
production bundle emits a >500 kB chunk warning (~7.9 MB `index-*.js`) —
pre-existing and unrelated to this backend-only ticket.
