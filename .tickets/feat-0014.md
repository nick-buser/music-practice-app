## Description

Groomed as **SB4** in `.tickets/_grooming-sketchbook-and-media.md`.

**Tier:** T1
**Depends on:** SB3b (merged, feat-0008)

**Why:** The decisive argument for living in Soundings: one timeline. A
practice session can sit in front of a sketch.

**Scope / surfaces / files:**
- `app/src/data/subject.ts`: `SubjectKind` adds `'idea'`; `resolveSubject`
  stays synchronous for bundled subjects; new `subjectFromIdea(idea)` builds
  a `Subject` (title = title or `#<handle>`, byline = kinds joined, abc =
  undefined, meter = idea.meter or `4/4`, bpm = idea.bpm or 80,
  `hasPieceDetail: false`). Subject ids for ideas are `idea:<uuid>`.
- `App.tsx` / `SessionView.tsx`: `startSession('idea:<uuid>')` resolves via
  `useIdeas` when live; return view is `sketchbook`. SessionView renders
  without a score when `abc` is undefined (already tolerated — verify).
- `IdeaPage.tsx`: "Practice this" button.
- Backend: none — `practice_sessions.subject_id` is a free string.

## Notes

Merged as PR #26 (`3b6c7d0`); CI green (#61, #62) before merging. Full
account in `work_history/feat-0014.md`. 298 tests across 32 files, was 291.

**The design decision:** `resolveSubject` stayed synchronous and untouched.
Bundled pieces/scales resolve from static data; an idea cannot, since it
lives behind the API. Making `resolveSubject` async would have dragged a
network call into a pure function the public static build also uses.
`subjectFromIdea` is pure; the caller supplies the idea.

**Verified rather than assumed:** SessionView's `abc === undefined` fallback
was genuinely pre-existing — but dead code until now, since every bundled
subject has `abc`. `App.test.tsx` exercises that branch live for the first
time.

Frontend only. All three criteria are `unit`, so this ticket closes
completely.
