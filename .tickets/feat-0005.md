## Notes

**Link kinds are verbatim from the design doc.** The eight kinds
(`derived_from`, `variant_of`, `resembles`, `might_fit_with`, `inspired_by`,
`incorporated_into`, `responds_to`, `mentions`) come from
`docs/sketchbook.md`'s `idea_links` table and were cross-checked identical
across the `IdeaLinkKind` Literal, the model `CheckConstraint` and the
migration `CheckConstraint`.

**Handle minting deliberately ignores soft deletes.** `max(handle) + 1` per
user is computed *without* a `deleted_at IS NULL` filter, so a soft-deleted
idea's handle is never reused (an explicit criterion). Concurrent creates can
still race to the same max, so the insert retries on the unique violation,
bounded at five attempts. A test forces a stale mint to prove the retry
recovers, rather than only proving sequential creates happen not to collide.
The `db.rollback()` in that retry assumes `create_idea` is the first write of
its request — documented at the call site; a future caller that writes before
creating an idea would lose that write.

**Both known traps are guarded here.** FK ordering (OPS2, hit again in PV1):
`create_idea` flushes the idea before `_sync_mentions` adds any `IdeaLink`,
with a comment pointing at the longer version in the provenance repository,
plus an integration test against real Postgres — the SQLite suite cannot see
that regression. `to_camel` aliases (PV1): every new wire field was checked
for the digit→letter capitalisation bug; none of SB1's trip it.

**Follow-ups found, not fixed (out of scope):**
- `get_idea_links` does not filter the *other* idea by `deleted_at IS NULL`,
  so a link to a since-soft-deleted idea still surfaces in `linksIn`/
  `linksOut` with that idea's stale handle and title. Soft-deleting an idea
  likewise does not clean its `IdeaLink` rows.
- `list_ideas` applies the `kind`/`tag` filters in Python after a single SQL
  fetch, because JSONB containment has no portable SQLite equivalent. Fine at
  single-tenant scale; SB5 owns real search.
- PATCH follows the existing house convention (`if data.x is not None`), so a
  client cannot explicitly null out `title`/`key`/`meter`/`bpm` once set.
  Pre-existing pattern in `chords.py`/`sessions.py`, not introduced here.
