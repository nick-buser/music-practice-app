## Notes

Merged as PR #25 (`dd17066`); CI green (#58, #59) before merging. Full
account in `work_history/feat-0013.md`. All three criteria are `unit`, so
this ticket closes completely — nothing left for a human.

**Semantics chosen, and argued in `cadence.ts`'s doc comment:** never
recorded → `due` (no elapsed time to measure against the 2x threshold, so
`overdue` has no basis); exactly at the interval → `due` (`>=`, not `>`);
past 2x → `overdue`; unparseable timestamp → `due`. Both boundaries tested
at the exact millisecond and one ms short. "Off" is `interval_days = NULL`
only — `0` is rejected by both Pydantic and a DB CheckConstraint.

**Migration 0006 round-trip, verified in the orchestrating session** with
the table checked at each step, not just exit codes: present after upgrade,
gone after downgrade, present again after re-upgrade.

First migration since FX4 (fix-0007) made the Alembic chain runnable on
SQLite, so this one verifies its own `upgrade → downgrade → upgrade`
round-trip locally rather than substituting something weaker.
