## Description

The two Fable-shortlist design items from the 2026-07-12 delegation-scoping
pass (roadmap workstreams 2 and 3), plus the score-substrate design Nick
explicitly widened the scope to ("the way we're rendering the sheet music,
scribing it, marking it, and the ui over those libraries needs deep design
work"). Three interlocking docs in `docs/`:

- `docs/score-substrate.md` — canonical ScoreDoc AST (TS, id-stable,
  serializes to MEI for Verovio), native/foreign score tiers, the
  anchor/annotation/layer contract, ScoreSurface component stack, staged
  editor path (E0–E3). Decisions keyed to Nick's answers: full-editor
  ambition, desktop-first marking.
- `docs/sight-reading-generation.md` — piano-first technique taxonomy
  (12 dimensions × rung ladders), transparent feature-budget difficulty
  scorer, deterministic constraint-based generator (recipe = version+spec+
  seed), MIDI-first assessment, legible Elo-lite calibration.
  Client-side TS so generation works on the public showcase build.
- `docs/recordings-provenance.md` — MediaRecorder+MIDI capture, Garage
  storage (service-0263 buckets), the extraction_runs/extracted_properties
  provenance contract (raw immortal, derived recomputable, producers
  named), mlserve extractors behind enqueue→poll, time-anchored
  annotations, staged score↔audio alignment bridge.

Each doc ends with implementation seeds + tier stamps for the grooming
pass that follows.
