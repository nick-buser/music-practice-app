## Notes

**Insert ordering is load-bearing here.** The completed-run path inserts a run
and its property children in one transaction — the exact shape OPS2 found has
no guaranteed order (no `relationship()` anywhere in `app/models/`, so the
unit of work has no dependency to sort on; SQLite tolerates it, Postgres
raises `ForeignKeyViolation`). `get_or_create_completed_run` flushes the run
before constructing any property, with a comment saying why. An
`@pytest.mark.integration` test covers it against real Postgres in CI, since
the default SQLite suite structurally cannot.

**`to_camel` mangles digit→letter boundaries.** `input_sha256s` generates the
alias `inputSha256S`, not `inputSha256s`. Unfixed, the API silently discards
client-sent input hashes and defaults to `[]` — which changes the params hash
and therefore run identity. Pinned with an explicit
`Field(alias="inputSha256s")`. Any future field with digits followed by
letters in one segment needs the same explicit alias.

**Deliberate deviations from the groomed text:**
- `latest_properties` takes a `user_id` (the grooming shorthand omitted it).
  Every other read in this codebase is owner-scoped; that is `OwnedMixin`'s
  stated purpose.
- `executor`/`status` are `String` + `CheckConstraint`, not SQLAlchemy `Enum`.
  Nothing else in `app/models/` uses `Enum`, and a native Postgres enum needs
  a `DROP TYPE` in the downgrade that a CHECK constraint does not — which now
  matters, because CI round-trips migrations.
- The `idea_assets.run_id` FK is **not** added here: SB2 has not landed, so
  `idea_assets` does not exist. Per the grooming doc, whichever lands second
  owns that FK — it falls to SB2.

**Follow-up found, not fixed (out of scope):** `migrations/versions/0001_initial.py`
uses `postgresql.JSONB()` directly for `saved_chords.identity`, which cannot
compile under the SQLite dialect (`CompileError`). Pre-existing — reproduced on
a clean pre-PV1 checkout. Harmless in practice (Alembic only runs against
Postgres; dev/test use `Base.metadata.create_all`), but it means
`alembic upgrade head` can never be run against SQLite. `0002_provenance`
deliberately uses `sa.JSON().with_variant(postgresql.JSONB(), "postgresql")`
instead so it does not repeat the bug.
